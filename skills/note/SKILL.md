오답 정리는 해설을 보며 몰랐던 내용을 다시 공부한 다음, 자기만의 언어로 다시 쓰는 과정이다. 이 스킬은 그 앞뒤를 맡는다. 앞(기본)은 해설을 공부하며 생긴 질문과 이해를 확인하고 오답노트를 만드는 일, 뒤(`check`)는 다 쓴 오답노트를 검사하는 일이다. 오답노트를 쓰는 것 자체는 사용자가 해설을 닫고 한다(기본은 손글씨, `chat`이면 대화창). 오답노트는 PDF로만 남기고 학습 로그로 옮기지 않는다.

# 경로와 공용 규칙
`<SKILL>`은 이 스킬의 기본 폴더, `<ROOT>`는 플러그인 루트(`<SKILL>/../..`)다.
- 경로: `<NOTES>`는 `${user_config.notes_path}`, `<GENIUS>`는 `${user_config.genius_path}`다. 셸에서는 공백이 있을 수 있으므로 항상 따옴표로 감싼다. 폴더나 파일이 없으면 만든다.
- 학습 로그 형식: `<ROOT>/references/learning-log-format.md`
- 질문과 틀린 이해의 기록: `genius:question` agent

# 1. 입력 해석
- 인자가 없거나 해설지 경로면 **해설 확인**(2번) 뒤 **오답노트 만들기**(3번)를 이어서 한다. 경로가 없으면 `<GENIUS>/시험`과 `<GENIUS>/복습`을 함께 보고 가장 최근에 수정된 해설지(제목이 `해설지:`, 예전 파일은 `채점:`)를 쓴다.
- 인자가 `check`면 **오답노트 검사**(4번). 경로가 없으면 `<GENIUS>/오답`에서 가장 최근에 수정된 오답노트를 쓴다.
- 인자가 `chat`이면 **대화형 오답노트**(5번).
- 예전 문법 `save`가 들어오면 "오답노트는 더 이상 학습 로그로 옮기지 않는다. 검사는 `check`로 한다"고 한 줄로 알리고 4번을 한다.

# 2. 해설 확인
잘못 이해한 채로 오답노트를 쓰면 틀린 내용을 외우게 되므로, 오답노트를 만들기 **전에** 한다.

1. 해설지 PDF, 같은 날짜의 답안지, 원 노트를 읽는다.
2. 문항별 "질문·내 이해" 칸의 필기(해설 상자 주변의 밑줄, 동그라미, 물음표 표시 포함)를 표로 옮겨 적어 보여 준다. 채점이 아니므로 확인을 기다리지 않고 바로 답하되, 판독이 불확실한 부분만 표시하고 "다르면 알려 달라"고 한다. 필기가 없는 문항은 건너뛴다.
   - 다른 기기에서 한 필기는 동기화로 넘어오는 데 시간이 걸린다. 파일 수정 시각이 채점 시각과 같고 필기가 없으면, 몇 초 뒤 다시 확인한다.
   - 필기를 읽는 동안에는 해설지를 바꾸지 않는다. 사용자가 다른 기기에서 열어 필기 중일 수 있고, 동기화가 겹치면 필기가 사라질 수 있다. 바꾸는 것은 5번에서 한 번만 한다.
   - 질문이나 이해 필기가 하나도 없으면 "확인할 필기가 없다"고 한 줄로 알리고 3번으로 넘어간다.
3. 문항마다 답한다.
   - **모르는 표현·질문**: 짧고 쉽게 설명한다. 이 문제의 맥락에 맞는 예를 하나 든다.
   - **내 이해**: `맞음 / 일부 틀림 / 틀림`으로 판정하고, 틀린 부분이 있으면 어디가 왜 틀렸는지와 바르게 고친 문장을 준다. 사용자 문장 자체는 고쳐 쓰지 않는다.
4. 질문한 표현과 **틀린 이해**는 `genius:question` agent를 백그라운드로 불러 학습 로그와 TIL에 기록한다. 프롬프트에 사용자 문장 원문, 배경, 답의 핵심, 잘못 안 것, `<NOTES>`와 `<GENIUS>` 경로를 넣는다. 배경은 "해설지 N번 해설을 읽다가 ~을 몰랐음"처럼 적는다(질문은 "개념 질문", 틀린 이해는 "이해 확인" 행). 맞은 이해는 기록하지 않는다.
5. **답변을 해설지에도 적는다.** 사용자가 필기를 마치고 부른 것이므로 이때는 파일을 바꿔도 된다. 단, 바꾸기 직전에 파일 수정 시각이 읽은 시점과 같은지 확인하고, 다르면 다시 읽는다.
   - 원래 파일을 그 시험지가 있는 폴더의 `.원본/<해설지 파일 이름>(note 전).pdf`로 복사해 둔다.
   - 숨김 표시가 있으면 문항 단위로 자른다: `python3 "<ROOT>/scripts/cropq.py" "<해설지.pdf>" <스크래치패드>/chk <문제 수> 99 "" "@Q"`. 새 HTML에 문항마다 블록 이미지(`chk/qN.png`, 필기 포함), 그 바로 아래 **파란 답변 상자**(왼쪽 파란 선, 옅은 파란 배경, 라벨 `질문 답변` 또는 `내 이해 확인 · 맞음/일부 틀림/틀림`, 회색 작은 글씨로 내 질문·내 이해 원문, 그 아래 답변)를 넣는다. 필기가 없는 문항은 블록 이미지만 넣는다.
   - 숨김 표시가 없는 예전 해설지는 페이지 단위로 한다. `python3 "<ROOT>/scripts/renderpages.py" "<해설지.pdf>" <스크래치패드>/pages <페이지 수>`로 페이지마다 필기째 이미지로 만들고, 그 페이지에 있는 문항들의 답변 상자를 페이지 이미지 바로 아래에 넣는다.
   - `python3 "<ROOT>/scripts/html2pdf.py"`로 PDF를 만들어 읽어 본 뒤, 같은 이름으로 덮어쓴다. 새 파일에도 숨김 표시를 그대로 넣어 두어 다시 확인할 수 있게 한다.

# 3. 오답노트 만들기
1. 이 해설지의 답안지(`<GENIUS>/.답안지/`)에서 문항마다 `grade`가 적어 둔 `오답노트` 줄을 읽고, `헷갈림` 또는 `모름`인 문항을 고른다. 없으면 "오답노트에 넣을 문항이 없다"고 알리고 끝낸다. `오답노트` 줄이 없는 예전 답안지면 학습 로그 원래 행의 이번 결과와 원인으로 `grading.md`의 표대로 정한다(원인 `개념 공백`이면 모름, `오개념`·`혼동`·`적용 실패`·`표현 부족`·`참고함`이면 헷갈림).
2. 같은 날짜의 오답노트가 이미 있으면 다시 만들지 않는다(사용자가 필기 중일 수 있다). 바꿀 문항이 생겼으면 사용자에게 묻는다.
3. 오답노트 PDF를 만든다.
   - 경로: `<GENIUS>/오답/YYYY-MM-DD 오답노트.pdf` (복습이면 `YYYY-MM-DD 복습 오답노트.pdf`). 폴더가 없으면 만든다. 시험지와 같은 HTML → PDF 방식(`python3 "<ROOT>/scripts/html2pdf.py"`)으로 만든다.
   - 제목 `오답노트`, 안내 한 줄: "해설을 읽고 시험지를 닫은 뒤 자기 말로 쓰기. 막히면 막힌 데까지만 쓰기. 분량은 자유."
   - 문항마다 번호, 원래 문제(한 줄), 내 답(원문), 판정, 빈칸 틀, 답안칸(약 150pt). 복습이면 **이전 정리**(6번)도 넣어 무엇이 달라졌는지 비교하며 쓰게 한다. **정답과 해설은 넣지 않는다.** 이 파일을 쓰는 동안 답이 눈에 들어오지 않게 하기 위해서다.

| 종류 | 빈칸 틀 |
|---|---|
| 헷갈림 | "나는 ___라고 생각했다 → 실제로는 ___ → 왜냐하면 ___" |
| 모름 | "___는 ___이다. 그래서 ___" (정의 + 그 결과로 생기는 일) |

4. 마무리로 오답노트 위치를 알리고 "이제 시험지를 닫고 오답노트를 쓰라"고 안내한다. 확인한 내용을 그대로 옮겨 적지 말고 기억에서 꺼내 쓰라고 한 줄 덧붙인다. 다 쓰고 검사받고 싶으면 `/genius:note check`를 하라고 알린다.

# 4. 오답노트 검사 (`check`)
자기 말로 쓰다가 틀린 이해가 생길 수 있으므로, 다 쓴 오답노트를 해설과 대조해 짚는다. 검사는 대화창에서만 하고 파일은 바꾸지 않는다.
1. 오답노트 PDF와 같은 날짜의 답안지, 해설지를 읽는다.
2. 필기를 문항별로 옮겨 적어 보여 준다. 판독이 불확실한 부분만 표시하고 "다르면 알려 달라"고 한다. 아직 안 쓴 문항은 건너뛴다.
3. 문항마다 맞은 부분과 빠진 부분을 1~2줄로 짚는다. 사용자 문장 자체는 고쳐 쓰지 않는다. 문장이 "헷갈렸다" 같은 감상이면 개념 문장으로 쓰는 게 효과가 크다고 한 번만 알린다.
4. **틀린 이해**가 드러나면 `genius:question` agent를 백그라운드로 불러 학습 로그와 TIL에 기록한다(2번의 4와 같은 방식, 배경은 "오답노트 N번을 쓰다가 ~라고 이해했음"). 빠진 부분이 크면 원래 행의 원인을 갱신할 수 있다(예: `개념 공백` → `오개념`).

# 5. 대화형 오답노트 (`chat`)
대화창에서 오답노트를 쓰고, 다 끝나면 쓴 내용을 다듬어 기본 모드와 같은 모양의 오답노트 PDF로 정리한다.
1. 대상 문항은 3번의 1과 같다(대상 해설지는 1번과 같이 정한다). 같은 날짜의 오답노트 PDF가 이미 있으면 새로 만들지 않고 사용자에게 묻는다.
2. 시작할 때 "해설지를 닫고 기억에서 꺼내 쓰기. 막히면 막힌 데까지만, 분량은 자유"라고 안내한다.
3. **한 번에 한 문항씩** 번호, 원래 문제(한 줄), 내 답(원문), 판정, 빈칸 틀을 보여 준다. 복습이면 이전 정리(6번)도 보여 준다. **정답과 해설은 보여 주지 않는다.**
4. 사용자가 쓰면 평가하지 않고 다음 문항으로 간다. 사용자가 중간에 질문하면 답하되, 그 문항의 정답을 대신 써 주지 않는다.
5. 마지막 문항까지 받으면 4번의 3~4처럼 문항마다 맞은 부분과 빠진 부분을 대화창에 짚고, 틀린 이해는 기록한다.
6. 오답노트 PDF를 만든다. 경로·제목·문항 구성은 3번과 같고, 답안칸 자리에 사용자가 쓴 내용을 **다듬어 정리한 글**을 넣는다. 문장을 읽기 좋게 고치고 빈칸 틀의 흐름에 맞춰 정리하되, 사용자가 쓰지 않은 내용은 보태지 않는다. 5번에서 짚은 빠진 부분은 그 문항 끝에 `빠진 부분: ...`으로 표시한다. PDF를 읽어 확인한 뒤 위치를 알린다.

# 6. 이전 정리 찾기 (복습 문항)
복습 문항의 이전 오답노트 정리는 학습 로그로 옮겨 두지 않으므로 오답노트에서 직접 찾는다. 원래 행의 `이력`에 있는 시험 날짜로 `<GENIUS>/오답/`의 오답노트(`YYYY-MM-DD 오답노트.pdf`, `YYYY-MM-DD 복습 오답노트.pdf`)를 찾고, 같은 문제의 문항에서 사용자가 쓴 정리(대화형이면 `빠진 부분` 표시 포함)를 읽는다. 없으면 생략한다. `grade`(복습 해설지)와 `review`(출제)도 이 방법을 쓴다.

# 주의
- 응답은 한국어로 하고, 부연 설명에 em-dash(—)를 쓰지 않는다.
- 쓰기는 해설지(와 그 폴더의 `.원본/`), `<GENIUS>/오답/`에만 한다. 학습 로그와 TIL은 `genius:question` agent가 쓴다(원인 갱신만 직접 한다).
