# TIL 형식

TIL(오늘 알게 된 것)은 `question`과 `note`가 쓰고, `test`와 `review`가 출제·채점 근거로 읽는다. 위치는 `<NOTES>/YYYY-MM-DD.md`(질문한 날짜)이고, 날마다 파일 하나다. 제목만 훑어도 무엇을 몰랐는지 보이게 쓴다.

```markdown
# YYYY-MM-DD TIL

## 듀얼랜이 무엇인지 모름
듀얼랜은 서버 한 대가 랜카드(NIC) 2개 이상으로 서로 다른 실제 IP를 쓰는 구성이다(예: 서비스망과 관리망).
NAT IP나 L4 VIP는 장비가 변환해 주는 주소라 서버 자신의 IP가 아니므로 해당하지 않는다.

- 배경: 서버 자산 관리 시트에 듀얼랜 사용 여부를 적어 달라는 요청을 받았는데, 듀얼랜이 뭔지 모르는 상황이었음.

## API Key와 로그인 토큰이 같은 것이라고 알고 있음
API Key는 호출하는 시스템을 식별하는 값이고, 로그인 토큰은 로그인한 사용자를 식별하는 값이다.
시스템은 바뀌지 않으니 API Key는 고정값을 쓰고, 사용자 세션은 끝나야 하니 토큰은 로그인마다 발급되고 만료된다.
둘 다 Authorization 헤더로 보낼 수 있어서 같아 보이지만, 확인하는 대상이 시스템이냐 사용자냐가 다르다.

- 배경: 외부 API 명세에 API Key를 Bearer 헤더로 보내라고 되어 있었는데, 로그인 토큰도 같은 헤더로 보내다 보니 API Key도 토큰이라고 생각했음.
```

- **제목**은 몰랐던 상태를 쓴다. 모르던 것은 `~을 모름`(원인 `개념 공백`), 틀리게 알던 것은 `~라고 알고 있음`(원인 `오개념`)으로 쓴다.
  - 한 제목에 몰랐던 것 하나만 쓴다. 한 질문에서 둘이 드러나면 제목을 둘로 나눈다.
  - `~을 모름` 제목에는 정답을 넣지 않는다. `Bearer가 무엇인지 모름` ○, `Bearer가 전달 방식이라는 것을 모름` ✗. 학습 로그 `몰랐던 것`에 그대로 들어가는데, 그 표에는 정답을 적지 않기 때문이다.
  - 학습 로그 행의 `몰랐던 것`과 같은 말로 쓴다. `review`가 이 제목으로 TIL을 찾는다.
- **본문**은 이름표 없이 맞는 내용을 쓴다. 무엇이 맞는지, 왜 그런지(원리나 목적)를 쓰고, `~라고 알고 있음`이면 헷갈린 것과 어디서 갈리는지도 쓴다. 보통 2~4문장이다. 그날 하던 일 이야기는 넣지 않는다. 확신이 없으면 끝에 `(확신 낮음)`을 붙인다(복습 채점에서 단정하지 않게).
- **배경**은 어떤 일을 하다가 무엇을 몰랐는지 한 문장으로 쓴다. 복습 문제를 실무 상황으로 낼 때 쓴다. 질문 원문을 따옴표로 옮기지 않는다. 회사·서버·서비스·사람 이름은 빼고 일반적인 말로 바꾼다.
- 필요할 때만 덧붙이는 줄: `- 노트: [[노트 이름]]`(학습 로그 행이 실제 노트에 연결될 때), `- 근거: 명령(본 값)`(실제 명령으로 확인했을 때).
- 같은 날 같은 몰랐던 것을 또 물으면 새 제목을 만들지 않고, 그 제목의 본문을 보강한다.
- 사용자가 자기 말로 정리한 문장은 TIL이 아니라 학습 로그 `내 한 줄`에 둔다.
